# BUG-18 / P2 · 继续世界列表全量读档带来 UI 卡顿

- **来源：** [第四轮静态 BUG 审计 BUG-18](../../docs/audits/联机MOD第四轮静态BUG审计与Agent修复交接-20261017.md)。
- **状态：2026-10-21 V1.63 Core 轻量目录、Entry 后台所选校验与可恢复删除源码完成，三端仅构建打包成功；运行/真实性能验收仍待用户执行。**
- **证据：** `SaveStore.ListWorlds` 当前调用真实 `Load`，每个世界都计算完整 SHA256 并反序列化整个世界，Unity 列表同步刷新可能随存档大小线性阻塞。
- **必须完成：** 在保护 BUG-03/15 的有效备份恢复和原代 SHA 检查前提下，设计可验证的懒加载/分页/异步列表健康摘要；实际选择时仍需完整验证、不能把解析成功的损坏指针当成可继续。合成多存档(1/10/50份)测 UI 帧耗时、IO、内存及损坏档判定，取得真实数据后按小补丁实施并验收。

## 本轮用户验收（V1.63）

本轮用户要求开发完成后由其验证，未代跑游戏或性能用例。实现记录见 [继续世界卡顿与删除实现](../../docs/reports/继续世界卡顿与删除实现-20261021.md)。本卡仍保留待办，不因构建成功而移为已完成。

- [ ] 点击“继续世界”先展示页面，列表加载期间界面可响应；不扫描解析所有世界正文。
- [ ] 选择存档后仅校验当前世界；快速连续切换、刷新、关闭重开，不被旧任务结果改回旧选择或提前开放续开。
- [ ] 损坏当前代/仅备份可恢复/双代损坏显示正确；实际续开保持 SHA 和备份保护。
- [ ] 删除确认能区分同名世界；取消不改动，确认后仅选中世界从列表移除，完整文件保留在本地回收目录。
- [ ] 运行、创建、续开、退出过程中不可删除；删除过程中不能从按钮或好友邀请开始新会话。
- [ ] 删除失败、目录被外部修改、关闭窗口再重开时，无错误成功提示、重复移除或误删其他存档。
