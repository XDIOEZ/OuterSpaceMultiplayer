# Agent 待办 / 已完成

本目录将其他 Agent 的交接事项拆成**有验收标准的独立 MD 任务卡**。源文档保留原位作为审计与需求依据，不因为关闭一个子任务而移动整份仍有未完成事项的报告。

- `待办/`：进行中、待修复、待原 Owner 签收、待实测或被阻塞的任务。
- `已完成/`：任务卡列出的**全部验收条件**有证据时，直接将原 MD 从 `待办/` 移动至这里，不是复制一份空报告。
- 读任务前须遵守仓库 [AGENTS.md](../AGENTS.md)、[协作记录](../AGENT-COORDINATION.md)、[Agent 邮箱](../agent-mailboxes/README.md) 与 [Git 规则](../GIT-COMMIT-POLICY.md)。

## 处理流程

1. 认领：读对应源文档与上下游消息，在协调表登记精确范围；避免覆盖旧的混合未提交代码。
2. 修复：仅修改明确允许的文件或 hunk；检查协议、存档、地图任期与保存确认是否受到影响。每项独立 BUG 修复按仓库规则递增版本并单独提交。
3. 验证：将**实际执行结果**与尚未执行的项目分别写在卡中，不凭静态推理宣布双端运行通过。
4. 归档：全部卡内验收条件满足后更改状态并执行文件移动，更新同卡相对链接和协作台，使用独立 Git commit。源码闭包或实机证据缺失的卡只能继续放 `待办/`。

本目录为**手动异步 Git 任务管理**，不执行后台监听、不自动通知，邮箱留言不等于相关 Agent 已读或已同意。
