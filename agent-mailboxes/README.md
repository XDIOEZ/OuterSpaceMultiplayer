# Agent 邮箱 · 使用说明

本目录是仓库内 Agent 的**异步 Markdown 留言区**：不同 MD 文件对应不同收件人或角色，任何 Agent 均可编辑自己的邮箱及其他 Agent 的邮箱，用于通知、提问、回复和任务交接。

**注意：**这里只是 Git 追踪的文件，不提供实时推送、自动轮询、锁或“已读”检测；没有实际读取和回复前，不得把消息当作对方已收到。任务占用、权限、冻结、接口约定与未完成依赖仍以 [AGENT-COORDINATION.md](../AGENT-COORDINATION.md) 为准，Git 提交依照 [GIT-COMMIT-POLICY.md](../GIT-COMMIT-POLICY.md)。

## 默认邮箱

| 文件 | 收件对象 | 用途 |
| --- | --- | --- |
| [ALL.md](ALL.md) | 所有 Agent | 需要大家主动阅读的公告、冻结与交接提醒 |
| [MAIN.md](MAIN.md) | 主控 / 集成 Agent | 协调、跨模块决策、构建与集成问题 |
| [TRANSPORT.md](TRANSPORT.md) | 网络 / Transport Agent | 连接、传输与通信协议实现问题 |
| [SESSION.md](SESSION.md) | 会话 / 持久化 Agent | 房间状态、权威、存档与会话生命周期问题 |
| [GAME.md](GAME.md) | 游戏适配 Agent | 原生游戏 Hooks、世界、舰队、地图与地表同步问题 |
| [UI.md](UI.md) | UI / Entry Agent | 面板、导航、显示与交互问题 |

这些名称是**角色邮箱，不代表某个 Agent 当前已在线或已认领**。实际负责人先查协调表。同一角色若有多个独立 Agent，创建 `<唯一-agent-id>.md` 独立邮箱并在此表登记；不要让多个实例误以为同一邮箱只属于自己。

## 收信、投递与回复

1. **开始任务时：**先读仓库 `AGENTS.md`、`Agent.md`、`AGENT-COORDINATION.md`，然后读 `ALL.md` 和自己的邮箱。结束任务或进入跨模块修改前，再检查一次。
2. **发信：**在收件人的 MD 文件末尾追加完整消息；多人协作中优先追加而非重写整份文件。多个收件人涉及共同规则时，发往 `ALL.md`；紧急协调也在 `MAIN.md` 告知主控。
3. **收信：**处理者可在自己邮箱的消息下补充处理进展并更新状态；需回复时，向原发件人的邮箱另写一条消息，填写原消息 ID，确保对方按自己的邮箱也能看到回复。
4. **状态：**`待处理`、`已读`、`处理中`、`阻塞`、`已完成`、`仅通知`。只能在实际动作发生后改变状态；补充处理者、时间和结果。不要删除他人原始留言；错误内容追加勘误。
5. **并发与 Git：**文件没有互斥锁。多人同时写同一邮箱先在协调表约定时间或由主控串行合并；写入前复读最新内容，提交前复核 diff，只暂存本轮改动。同一个 Git index 不可被多个 Agent 同时提交，发现冲突停止并保留所有消息。
6. **边界：**发信不能自动授权修改对方正在占用的文件，不能解除冻结、替代代码审查或用户授权；不得在邮箱存放密码、令牌、恢复码、私人身份信息、房间密钥等敏感数据。

## 每条消息格式

使用唯一消息 ID（日期时间、发件人标识、序号），标题应让收件人无需翻上下文就知道事项：

```md
### MSG-YYYYMMDD-HHMMSS-<发送者ID>-01 — 简短标题
- 发件人：<Agent 标识 / 任务 ID>
- 收件人：<目标邮箱名>
- 时间：YYYY-MM-DD HH:mm +08:00
- 状态：待处理
- 关联任务/文件：<任务 ID；相关文件路径>
- 消息：<事实、风险、需要协调的事项>
- 需要回复：<明确的问题、期望结果；若没有则填“无”>
- 回复关联：<如果是回复，填原消息 ID；否则填“无”>
- 处理记录：<收到后再补充实际处理人、时间与结果>
```

邮件内容尽量短；需要大量日志、代码差异或测试记录时，放到原任务的文档，并在消息里添加相对路径。完成的记录保留以便后续 Agent 追溯，不通过删除旧邮件来清空收件箱。
