# FreeWorldMultiplayer · 联机 V1

**开源代码 / BUG 反馈 / Pull Request：** https://github.com/XDIOEZ/OuterSpace

项目由一人维护，受限于时间和设备，跨机联机的测试覆盖非常有限。欢迎有开发想法的玩家提交 [Issue 和 PR](CONTRIBUTING.md)，帮助修复 BUG、优化性能与兼容性。本 MOD 仍属实验性项目，编译成功并不代表多人联机已经充分验证；使用前请备份重要存档。Steam 创意工坊拟发布简介见 [发布草稿](docs/publishing/STEAM_WORKSHOP_DESCRIPTION.md)。

原创代码许可见 [MIT License](LICENSE)。第三方库及原游戏资产保留各自权利。

文档按用途分类，入口见 [文档索引](docs/README.md)。

这是《Outer Space》的独立外部 MOD，分别面向本机 Steam 与 TapTap 游戏程序集构建。现行需求只以 [联机方案 V1.md](docs/plans/联机方案%20V1.md) 为准：独立联机世界、个人资产、唯一地表模拟、互访协作、关系与地表袭击、舰队互见、可靠保存属于同一次 V1 范围。

**代码、编译和运行验收是三个不同状态。当前开发产物必须结合包内 `BUILD-INFO.json` 判断其引用目标；生成 ZIP 不代表已通过游戏加载或跨机联机验收。** 开发不修改 Project3、Steam、TapTap 本体或共享 Harmony 依赖，不自动启用 MOD。

发布号以根目录 [VERSION](VERSION) 为唯一来源，发布内容见 [CHANGELOG.md](CHANGELOG.md)。每完成一个独立小 BUG，第二段整数递增一次：`1.9` 之后是 `1.10`；同一修复的重新构建和三端同步不重复升版。需求名称“V1”、游戏匹配目录 `v_common`、网络协议号和存档结构版本保持各自含义。

V1.39 使用网络协议 7，存档结构版本仍为 1；房主和客人都必须更新 MOD。敌对玩家舰队攻击后，防守方先收到拦截通知，选择迎战才进入战场；选择逃跑直接脱离本次拦截、继续既有航程。关闭通知不会代选，可以重新打开；未回应超时、关系改变和断线等取消尚未开战的拦截。保留此前的舰队表现、地表同步、入图屏障、SEED 地形及本地缓存与发行运行库兼容修复。构建和安装状态以包内 BUILD-INFO 及同步回执为准；游戏内效果由用户验收。详情见[舰队拦截交付记录](docs/reports/舰队拦截迎战与逃跑-20261019.md)。

地块缓存保存于 `%LOCALAPPDATA%\CatStudio\FreeWorldMultiplayer\map-cache-v1`，按渠道和实际运行目录隔离，世界与地块另有独立清单；退出游戏后保留，不绑定具体游戏小版本。默认最多 512 MiB、8192 个内容块和 64 个地图清单，按使用情况清理旧内容。再次入图先对照房主当前内容，只接收缺失或变化的块；校验通过后等待本次原生地图及其他玩家角色投影就绪，再按顺序应用后续变化。缺失、损坏或不兼容时重新获取，缓存不代替完整存档。流程见 [地块同步与本地缓存](docs/diagrams/地块同步与本地缓存.svg)。

同星系点击另一玩家的舰队，使用“攻击、交流、参观”入口。攻击要求双方已经敌对，双方进入战场后各自控制舰队；交流为当前房间内一对一消息；参观须对方同意，随后原版运输页固定为自己母舰向对方母舰单向赠送物资，不能反向获取库存。参观申请与未使用授权会在超时或离线后失效。结构见 [玩家舰队代理与交互](docs/diagrams/玩家舰队代理与交互.svg)。

游戏更新兼容按实际原生接口、资源是否存在及控件结构判断，不以 `0.9.0003`、`0.9.0004` 等具体游戏小版本作为运行白名单。UI 使用已确认的新旧资源键兼容；缺少必需接口或结构时仍明确报错，不跳过业务约束。安装时的程序集指纹核对用于防止装错构建目标，不是游戏运行版本锁；游戏接口发生不兼容变化时仍需重新适配。

原生归档类型仍只接受本机编译得到的类型闭包。接收时允许程序集内部 `Version` 不同，但类型名、泛型和数组结构、程序集名称、区域性与公钥标识仍须匹配；不根据网络字符串加载程序集或创建任意类型。旧归档输出保留，字段或类型确实不兼容时继续拒绝，不能把版本中性类型识别当成任意游戏版本或存档结构兼容保证。

构建把发布号写入 MOD 列表名称以及 DLL 的程序集版本；入口和面板显示实际已加载 DLL 的版本。`BUILD-INFO.json` 的 `ModVersion`、`AssemblyVersion` 与 `SourceRevision` 分别记录发布号、DLL 版本和源码指纹；DLL 的信息版本也包含发布号与该指纹。包内保留 `VERSION` 和发布记录，安装与同步回执记录相同版本。源码中的清单是版本占位模板，只安装构建后的包。

## 主仓库与运行副本

开发前阅读 [Agent.md](Agent.md)。唯一开发源是 `C:\Users\CatStudio\Desktop\FreeWorldMods\FreeWorldMultiplayer`；P3、Steam、TapTap 的 `mods\FreeWorldMultiplayer` 都是运行副本。历史 `artifacts/migrations` 工作目录不再作为开发、构建入口。

修改后在主仓库运行：

```powershell
& .\Sync-ModCopies.ps1 -BuildOnly          # 默认：只构建三端包，不安装

# 只有用户明确要求“安装”时，才执行下面的安装命令
& .\Sync-ModCopies.ps1                     # 构建并安装 P3、Steam、TapTap
& .\Sync-ModCopies.ps1 -Target Project3    # 只安装 P3
& .\Sync-ModCopies.ps1 -Target Steam       # 只安装 Steam
& .\Sync-ModCopies.ps1 -Target TapTap      # 只安装 TapTap
```

默认使用 `-BuildOnly`，只生成三端包，不覆盖运行副本。只有用户明确要求“安装”时，才去掉 `-BuildOnly`，先完成所有选定目标的构建，再分别备份和安装本 MOD；指定目标则只安装指定端。历史安装授权不延续到后续任务。三端 `BUILD-INFO.json` 的 `SourceRoot`、`SourceRevision` 记录同一份主仓库工作区，未提交的源码改动也会参与构建。DLL 使用不同目标依赖，字节不同属于正常情况。同步回执为 `artifacts/last-copy-sync.json`。

只有用户明确要求安装对应目标时，才运行副本内的 `Update-From-Main.ps1`：它会调用主仓库脚本并安装到对应游戏目录，TapTap 副本不会更新到 Steam 默认目录。默认“拉取、更新、同步”仍用主仓库 `-BuildOnly` 只打包。此“拉取”不执行 Git pull，不启动后台监视，不自动重启游戏。安装后按原版要求重新加载；游戏内验收由用户执行。

## 构建

要求 PowerShell 7、带 Roslyn 的 .NET SDK，以及本机 Unity 2022 的 `unity-4.8-api` 参考库。构建从只读 `Project3/Assembly-CSharp.csproj` 定位 Unity 引用，Harmony 从本游戏实际安装的 `com.harmony` 提供者解析；存在多个候选时使用 `-HarmonyPath` 显式指定。

基于当前 Project3 已生成程序集构建开发参考包：

```powershell
& .\build.ps1 -ReferenceMode Project3 -NoDeploy
```

输出：`artifacts/p3-development-reference/FreeWorldMultiplayer/` 与 `artifacts/FreeWorldMultiplayer-p3-development-reference.zip`。**它只表示编译参考了 Project3 当前生成的程序集，不声明兼容已安装 Steam 版本。** 不会复制 Project3 的 DLL 到游戏，也不会触发 Unity 重编译或打包本体。

以实际安装 Steam 游戏程序集为目标构建：

```powershell
& .\build.ps1 -ReferenceMode Steam -GamePath 'C:\Program Files (x86)\Steam\steamapps\common\Outer Space' -NoDeploy
```

输出：`artifacts/steam-target/FreeWorldMultiplayer/` 与 `artifacts/FreeWorldMultiplayer-steam-target.zip`。如果 Steam 版缺少代码需要的游戏接口，编译会明确报错，不以 Project3 DLL 替代。`BUILD-INFO.json` 记录目标、关键引用版本及 SHA-256、已安装 Steam 运行库的已知 Harmony 直接引用检查结果；这个元数据检查也不等于运行验收。`-NoDeploy` 默认开启，脚本拒绝关闭此开关。

## 安装与启用

1. 核对包内 `BUILD-INFO.json` 与目标游戏匹配。开发参考包应等待具有相应原生 API 与保留规则的游戏包，不能把它当作当前 Steam 版本兼容包。
2. 将目标包中的 `FreeWorldMultiplayer` 文件夹放入游戏的 `mods` 目录，仅安装本 MOD 的分发文件；保留其他 MOD 和已有玩家数据。
3. 在原生 MOD 管理页先启用 `Harmony (com.harmony)`，再启用名称含当前发布号的 `FreeWorldMultiplayer / 联机`，保存并按原生要求重启游戏。
4. 主菜单或游戏中的原生 Canvas 就绪后，右上角显示带发布号的“联机”入口。面板使用游戏已加载的按钮、中文字体和原生弹窗生命周期；Esc 或右上角关闭只关闭面板，不退出房间。

源码工作区也提供独立安装工具：先以实际目标目录完成 `-ReferenceMode Steam` 构建，再执行下列命令。工具核对包的程序集指纹和已知 Harmony 运行接口，备份并复制本 MOD 分发文件；不会改动其他 MOD、启用列表、P3、本体 DLL 或玩家存档。提供工具不表示已执行安装或游戏验收。

```powershell
& .\Install-Mod.ps1 -GamePath '实际目标游戏目录'
```

Project3 的 Editor MOD 目录：`C:\Users\CatStudio\Desktop\Project3\mods\FreeWorldMultiplayer`。使用 Project3 开发参考构建和该目录已有的 `mods\Mod_Harmony` 提供者，安装工具以 `-TargetType Project3` 核对实际 Editor 引用，只允许写入这个 MOD 子目录。Project3 的源码、设置、本体程序集及共享依赖仍不修改，也不自动启动 Unity。

```powershell
& .\build.ps1 -ReferenceMode Project3 -HarmonyPath 'C:\Users\CatStudio\Desktop\Project3\mods\Mod_Harmony\v_common\Assemblies\0Harmony.dll' -NoDeploy
& .\Install-Mod.ps1 -TargetType Project3 -GamePath 'C:\Users\CatStudio\Desktop\Project3'
```

Steam、TapTap 包由同一主仓库分别针对真实游戏构建，均包含独立 JSON 程序集，并使用统一的 `Socket.Accept` 实现。游戏更新后须重新针对真实程序集构建；不把 Project3 的本体 DLL 复制过去。安装是否已执行以同步回执为准。

TapTap 默认游戏目录为 `C:\TapTap\PC Games\242783`，使用其已安装的本地 Harmony；包输出到 `artifacts/taptap-target/FreeWorldMultiplayer`，不会覆盖 Steam 构建产物。

```powershell
& .\build.ps1 -ReferenceMode TapTap -GamePath 'C:\TapTap\PC Games\242783' -NoDeploy
& .\Install-Mod.ps1 -TargetType TapTap -GamePath 'C:\TapTap\PC Games\242783'
```

## 独立日志

MOD 从加载开始订阅 Unity 的线程日志，完整消息和异常堆栈按游戏渠道独立保存于：

- TapTap：`%LOCALAPPDATA%\CatStudio\FreeWorldMultiplayer\Logs\TapTap`
- Steam：`%LOCALAPPDATA%\CatStudio\FreeWorldMultiplayer\Logs\Steam`
- Unity Editor：`%LOCALAPPDATA%\CatStudio\FreeWorldMultiplayer\Logs\Project3`

每次启动使用独立文件；同一渠道多开也不会写入同一个文件。日志头记录发布号、进程、游戏及程序集路径，便于对上实际运行副本，不记录身份密钥或完整启动参数。日志写入在后台批量处理，避免回调逐条同步刷盘；写入失败会明确提示，避免日志递归。

Unity 原生 `Player.log` 保留原位置，MOD 不能在引擎启动后改它的路径。独立日志覆盖 MOD 订阅之后转交 Unity 的消息；不代替加载前日志、原生崩溃转储或 SDK 自写文件。旧混合日志不移动、不猜测归属。

V1.17 的 `[FreeWorldMultiplayer][slow-operation]` 记录主线程处理消息、协议编解码及发布地图/个人更新时超过 50 ms 的阶段，同阶段每 5 秒最多记录一次。记录包含阶段、毫秒数、消息字节数、地图编号及房主/客人角色；没有消息内容、昵称或登录凭证。它用于用户复测后区分剩余同步热点，不是已经完成性能验收的证明。

## 房间

- **新建**：在“创建 → 新世界”先从滚动列表选择已保存的**自定义世界配置**，再填世界名、人数上限、每人基地上限、开局雇员总数和监听端口，点击“创建并开房”。只列自定义世界，不列官方方案；未选择有效配置时不能开房。创建期间会显示状态，同一时间只接受一次创建请求；生成完成并保存后才开放房间。不导入单机世界；每位玩家只在首次进入该世界时领取一次母舰与初始资产。
- **取消创建**：点击创建遮罩即可取消；需等待本次生成安全结束后返回，取消的世界不会保存或开放房间。
- **续开**：在“创建 → 继续世界”的滚动列表点击所需存档，查看名称、保存时间和详情，再点击“继续所选世界并开房”。端口和 Steam 开关可单独选择，人数上限和开局规则沿用存档；损坏存档展示原因并禁用续开。
- **全局设置**：页头“设置”管理默认开局雇员数、人数上限、每人基地上限、端口、Steam 房间及同星系出生开关，保存于独立数据目录的 `settings.json`。开局雇员总数默认 4 人，可设 1～32；每人基地上限默认 1 处，可设 1～64，母舰不计入。创建页可覆盖本世界配置，续开沿用该世界规则；已有世界和重连不重复赠送雇员。
- **同星系出生**：“新玩家与房主同星系出生”默认开启，可在新建页为本世界选择，创建后固定。开启时仅首次生成新玩家舰队使用房主当时所在的物理星系，并沿原版规则选取合法出生位置；关闭时使用原版选择，可能恰好同星系。重连不传送，旧世界缺少此字段按关闭处理，续开时不被新的全局默认值覆盖。
- **页面**：主页仅“创建 / 加入”，连接后切为“房间 / 玩家关系”；时钟、邀请、保存和退出在房间内显示。地块、营地和运输操作全部沿用原版界面，见 [原生操作流程](docs/diagrams/联机V1.4原生操作流程.svg)。
- **IP**：房主默认监听 `0.0.0.0`，客人填可达 IP 和同一端口。“IP 直连”使用独立托管 TCP，不初始化或调用 Steam。MOD 本身不会打开防火墙、端口转发或隧道。
- **Steam**：房主打开 Steam 好友房间开关后开房，同时保留 IP 通道；房间号出现后可复制或打开好友邀请。客人输入房间号加入，或接受邀请后在面板确认。切换房间会先请求原房间保存退出。
- **时钟**：只有房主可以暂停及设置倍速。攻击和冷却以不受倍速影响的现实时间累计；房主暂停时停表。
- **退出**：“保存并退出房间”走最终检查点与统一保存流程；收集期间继续处理网络并显示退出忙碌状态。会话实际结束后回到“创建 / 加入”，清除旧玩家及身份恢复确认；断线、握手失败也会收口，不残留可操作的房间页。房主退出会结束所有客人连接。保存失败必须以面板/日志错误为准，不能视作本轮进度已保存。

### 完全不启动 Steam 的配套启动路径

包内 `Launch-Direct.ps1` 以 MOD 自身 `DirectLaunch` 子目录为工作目录，在该目录生成开发用 `steam_appid.txt`，启动原游戏 EXE 并传入 `-fwm-direct`。**不在游戏根目录写入 AppID 文件，不复制或替换本体 DLL，不改本体/P3，不主动启动或结束 Steam。** 该参数还禁止 MOD 注册 Steam 邀请监听；选择 IP 直连即可。

这条路径依据 [Valve 官方启动约定](https://partner.steamgames.com/doc/sdk/api#initialization_and_shutdown)：AppID 文件存在时重启检查返回 false；Steam SDK 从当前工作目录查找它。已读 Project3 `SteamManager` 的 `SteamAPI.Init()` 失败分支仅返回，因而不会在此处主动退出游戏。实际游戏 EXE 是否还有包装器或其他启动约束仍须验收。

无 Steam 时原生加载器不会枚举工坊。须先将合法的 **Harmony 本地 MOD** 和本 MOD 在原生管理器中启用，再由用户自行退出 Steam。脚本会核对本地 `mods` 中是否存在唯一 `com.harmony`，找不到时明确报错；不会擅自复制工坊共享依赖。

`ChannelSteam.requestUID` 的原版失败分支会调用 `TryLaunchSteam` 并递归重试。直连启动的 MOD 初始化后会拒绝这两个 Steam 专属入口、显示明确原因，不产生虚构 Steam UID，也不启动该重试循环；联机身份继续使用独立随机凭证。未带 `-fwm-direct` 的普通 Steam 启动保留原渠道行为。

```powershell
# 只准备 MOD 自身启动目录，明确不启动游戏：
& .\Launch-Direct.ps1 -PrepareOnly
# 由用户执行实际直连启动：
& .\Launch-Direct.ps1
```

这是已经提供的启动实现，**尚未执行游戏启动验收**。如果本体在更早阶段阻止离线启动，必须报告真实失败链，不能把 TCP 可用等同于整款游戏已脱离 Steam。

## 玩家、地块与袭击

“玩家关系”页选择目标玩家并管理关系。友好需双方同意，敌对单方生效；关系不会阻止查看地块。通过原版地块“进入”查看其他玩家基地，切换视野离开时不自动撤军或结算物品。原版“创建基地”提交营地归属，首次营地自动成为正式基地，后续营地保持普通；达到每人上限后原版创建入口禁用，房主提交时仍会校验。通过原版入口废弃普通营地会释放名额，不删除地块内人物或物资；母舰和正式基地保持原版不可废弃规则。只有正式基地享受离线收益。

原生星球选点、进入地表和远征目标解析先提交位置意图，由房主确认唯一地图编号及生成地表。银河中的在线玩家舰队可见，航行意图交房主执行；公共势力、NPC 舰队、事件、设施及地图目录按白名单基线和增量同步。客户端不独立推进银河业务，也不为显示 NPC 擅自生成其舰船与编号；尚未被原版正式物化的 NPC 保留原版表现边界。

派遣、空投和返舰使用原版运输界面。敌对雇员前往离线玩家地块时，沿同一真实运输单进入袭击；纯查看和运输在途不启动袭击计时。原版返舰运输提交本场唯一撤离，房主确认容量和战果。正式基地、普通营地和其他占领地块均适用：

- 实际落地并完成战场就绪后计 10 分钟现实时间；本场开始离线的守军遇致死伤害改为倒地，防守者中途上线后仍保留本场保护。
- 只有一次撤离，战利品最多一个本场锁定出征空投仓容量；能装多少带多少，空仓提前撤离也结束进攻。
- 房主确认在期限内撤离并可靠保存后，战利品才成为进攻方永久资产。重复、过期或失败请求不会再次发放。
- 超时立即结束；未撤离的战利品留下，存活进攻雇员空手返回，伤亡及伤势保留。
- 上场结束后目标地块进入 60 分钟现实时间冷却，对所有进攻方共同生效。

## 数据与连接边界

本机身份凭证和联机世界保存在 `%LOCALAPPDATA%\CatStudio\FreeWorldMultiplayer`，不进入原版单机存档列表，不打包个人凭证或存档。相同昵称不合并资产，不能通过改名、IP 或临时连接号恢复其他人的玩家身份。首次资产、跨图转移、战果和撤离需保存确认；普通进度允许崩溃回退到最后完整保存代。

默认身份按实际渠道和游戏运行目录分别保存于 `identities/<渠道>/<目录指纹>/identity.json`，同机 TapTap、Steam、Editor 或不同游戏副本不会自动共用同一玩家。原根目录 `identity.json` 保留；第一个 Steam 副本可一次性认领旧默认凭证，其他副本生成自己的稳定身份，重启不重复换号。同一个身份的重复有效连接仍被拒绝。

显式“继续世界”时，可使用本机已有凭证精确匹配该存档的房主编号及密钥验证值，兼容此前由 TapTap 等副本创建的旧世界；匹配凭证仅用于本次房主会话，不覆盖当前副本的默认身份，不更改存档绑定，也不按昵称接管。凭证文件损坏或被另一进程占用时会明确报错，保留原文件。

凭证丢失时，在新设备的“设置”页复制本机登录恢复码，交给房主；内容只有新凭证编号与验证值，不包含 `Secret`。房主先在“玩家关系”选择原来的离线玩家，再到“房间”的登录身份恢复区粘贴恢复码，核对完整 `PlayerId` 后再次点击确认重绑。只有统一保存成功才显示完成；保留原玩家资产和首次领取标记，旧凭证撤销，不按昵称猜测或合并玩家。

消息和线程边界：TCP 长度帧、Steam 48 KiB 分片与严格连续重组；单消息最多 128 MiB、每个发送队列与总接收队列最多 256 MiB，超限明确终止连接，不截断或悄悄丢弃权威变更。Steam 重组超时 60 秒。TCP 网络线程只处理字节和线程安全事件队列；Unity、Steam API 和游戏业务由主线程处理。直接连接是游戏协议字节通道，不提供 TLS；不要把本机身份凭证公开或作为其他服务密码使用。

## 用户验收清单

以下是需要在目标游戏和多台设备上实际执行的验收，不代表开发工具已经代跑：

1. 原生 MOD 加载无异常；退出/重开面板不会残留遮罩或透传游戏输入；单机存档不被读写。
2. 新建与续开联机世界、Steam 好友邀请/房间号、IP 直连；单独验证整款游戏无 Steam 启动是否成立。
3. 两人首次进入、重连、重复连接、房满、断线：各自母舰、雇员、资金、科技和任务独立且不重复领资产。
4. 分图运行与同图参观：建筑、人物和物资实时同步；唯一模拟者断线后交接；无人普通地块冻结，正式基地按托管计工，不双算。
5. 三人关系 A-B 友好、A-C 友好、B-C 敌对；友好变中立立即停止工作；中立/敌对不自动拿取库存；友好随身赠送可带走。
6. 真实空投、远征、留人断线、重连带回：同一雇员不复制，转移不会同时存在于来源/运输单/目标。
7. 正式基地及普通营地袭击：守军倒地保护、10 分钟硬结束、单仓唯一撤离、提前空撤、超时空手返回、守方上线、60 分钟全局冷却。
8. 同星系所有在线舰队移动互见；离线舰队消失并冻结，重连不补航程及燃料。
9. 保存失败、杀进程与重新开房：全世界恢复同一完整保存代；关键事务失败不重复转移，旧会话/旧任期提交不能继续写入。
10. 新设备凭证恢复：明确选择原离线 PlayerId，成功保存后用新凭证恢复原资产，旧凭证不能再登录或重复领取；保存失败保留旧绑定。

本轮验证边界由用户决定：不自动启动游戏、Play Mode 或跨机测试；构建、包生成、安装与运行结果分别报告。
