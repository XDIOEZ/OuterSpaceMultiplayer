# FreeWorldMultiplayer · 第八轮双端性能对照说明

> 2026-10-17。对应 [第八轮优化开发案](联机插件优化开发案-第八轮实测驱动实施-20261017.md) 的 E8-03 / E8-04 / E8-05。**本文件不是游戏内验收结果。**

## 1. 已接入的真实计量工具

`src/Session/PerformanceWindow.cs` 的生产直方图增加 `ExportBinCounts()`：固定 14 桶、`histV=1`，分别代表耗时不超过 0.25/0.5/1/2/4/8/16/33/50/100/250/500/1000 ms，以及大于 1000ms 的溢出桶。

`SessionPerformance.cs` 与 `NativeGroundCaptureProfile.cs` 在原来的 `FWM_PROFILE=1` 开关下，只在约 30 秒汇总时追加 `histV=1 bins=...`，没有逐帧/逐实体日志。`tools/Analyze-MultiplayerDiagnostics.ps1` 则在原先的 JSON 中补充 `HistogramSchema` 和 `HistogramBuckets`。

新工具 `tools/Compare-MultiplayerPerformance.ps1` 会根据实际样本权重**合并各窗口的桶数**后计算总 P95 桶上界，避免把多个 P95 直接取平均；大于 1000ms 的桶以真实观测到的最大值作上界。结果仍是**上界估计**，不是精确原始样本的 P95。

## 2. 六组真实房主/客人日志

游戏进程启动前，双方都开启 `FWM_PROFILE=1`，并真正加载**相同的 `SourceRevision`**，按固定条件做同一个场景三轮基线、三轮优化后候选。`2026-10-16` 的旧日志没有本次 `histV=1` 数据，**不能用它们冒充新的基线**；基线必须来自本次新的计量代码**尚未修改优化算法**时的运行版本。

每轮由操作人员分别保存房主和客人的真实日志，并生成脱敏的双端 JSON：

```powershell
$pwsh = "$env:LOCALAPPDATA\CatStudio\FreeWorldMultiplayer\DevTools\PowerShell\7.5.4\pwsh.exe"
& $pwsh -NoProfile -File .\tools\Analyze-MultiplayerDiagnostics.ps1 -HostLog '第1轮房主日志.log' -GuestLog '第1轮客人日志.log' -OutFile .\artifacts\e8-real\baseline-1.json

# 同样生成 baseline-2、baseline-3、candidate-1、candidate-2、candidate-3
```

每一轮必须确认双方处于同一实际房间，并记录：匿名世界代号、相同地图格数/角色与建筑规模、设备、传输通道、人数、具体操作和游戏行为是否正确。客人舰队 `accepted` 不是实际到达；还须观察房主移动、客户端显示与 2D 角色/物资变化，确认无重复资产和地图修订错误。

## 3. 实际填报和合并对照

先复制 [可填写的 JSON 模板](联机第八轮双端性能对照模板.json) 到被 Git 忽略的 `artifacts/e8-real/experiment.json`。真实填写 `Players`（2～4）、`Entities`、`MapGrid`、网络、设备和场景步骤；`Target.Role/Stage` 选**真实观测的最慢阶段**。

每轮**只有操作人员实际核实**同一房间、相同条件、对应关键游戏结果通过后，才将 `OperatorConfirmedSameSession` 和 `OperatorConfirmedSameConditions` 改为 `true`，将 `GameplayCheck` 改为 `pass`。这些字段是**人工确认**，不等于工具从日志证明了玩家身份或实机正确性。

```powershell
& $pwsh -NoProfile -File .\tools\Compare-MultiplayerPerformance.ps1 -ManifestPath .\artifacts\e8-real\experiment.json -OutFile .\artifacts\e8-real\comparison-001.json
```

比较器要求三轮基线和三轮候选都有配对成功的两个运行端、合法且一致的已加载 DLL 指纹、固定 14 桶、每个被比较阶段每轮至少五个样本、合理的样本数差异以及完整的人工确认。任何环节缺失都**拒绝得出改善结论**，不补零、不假定成功。

只有目标 P95 **下降 ≥25%** 且其余可比较阶段恶化 **≤10%** 时，才报告 `PROFILE_GATE_MET_REQUIRES_RUNTIME_REVIEW`。该状态依旧**不是游戏验收通过**；还要通过人物行为、资产、ACK、断线和存档代回归。输出放在 `artifacts`，不覆盖以前的对照报告。

## 4. 纯逻辑验证与阻塞条件

```powershell
dotnet run --project .\tools\OptimizationChecks\OptimizationChecks.csproj -c Release
& $pwsh -NoProfile -File .\tools\Analyze-MultiplayerDiagnostics.ps1 -SelfTest
& $pwsh -NoProfile -File .\tools\Test-Compare-MultiplayerPerformance.ps1
```

比较器的合成用例会检查成功合并三轮、伪造源码指纹、桶数错误、只有两轮、没有游戏人工确认、目标无改善及其它阶段退化。**合成数据只是代码测试，不能当实际性能成果**。

已有 [源码交接清单](联机第五轮源码交接与放行清单-20261017.md) 的历史未跟踪和混合文件仍要由实际 Owner 收口，干净 Git 可复现、运行安装及双机现场验收都需要独立放行。第八轮本次只增强测量与比较判定，**没有改变世界模拟、同步协议、存档或玩家资产**。
