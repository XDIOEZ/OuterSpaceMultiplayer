## 已接入的真实调用链

`NativeMapReplicator.CaptureUpdate` 的现有操作依次测量：

| 固定日志阶段 | 覆盖的调用 | 解释 |
| --- | --- | --- |
| `ground.capture.entities` | `CaptureOwners`、集合读取、实体字段 `NativeWire.CaptureValue`、实体新增/修改/删除对照 | 区分对象数量与改变的实体数 |
| `ground.capture.fields` | 地图/地表的原生字段差量对照 | 字段扫描与实际业务提交不等价 |
| `ground.capture.tiles` | 2D `string[,]` 格子完整比较和必要的克隆 | 每次扫描格数与真正修改格数分开记录 |
| `ground.capture.poses` | 本地已加载地图中的角色/动物/怪物位置、动画、朝向和目标读取 | 只观察原生状态，不变更模拟者或添加远端 AI |
| `ground.capture.personal` | `CapturePersonalDeltas`，关联个人进度采集 | 不绕过个人进度修订 |
| `ground.capture.total` | 包括基线准备、快照/差量生成与以上所有阶段的整条成功捕获 | 分阶段采样不等于相加恰为 total；额外准备/后处理仍计在 total |

**开关**：在**启动游戏前**设置 `FWM_PROFILE=1`，或加 `-fwm-profile`。默认关闭；启用后只在主线程已有成功地表捕获路径累积直方桶。每约 30 秒发生下一次捕获时输出 `[FreeWorldMultiplayer][profile]` 的 P50/P95/P99 **桶上界**及真实最大耗时，并输出一条 `[FreeWorldMultiplayer][ground-counts]` 汇总：`captures / entitiesScanned / entityChanges / fieldsScanned / tilesScanned / tileChanges / posesSampled / poseChanges`。没有逐单位日志，不记录地图内容、坐标、玩家凭证或聊天。

**安全边界**：只为 `CaptureUpdate` 插入固定阶段的测量入口，原来的实体变更、修订、`AuthorityEpoch`、同图唯一模拟、FIFO、ACK、SEED 和完整存档逻辑不变。探针出错不会把成功的原生事务变成联机失败。不得把 `ground-counts` 中的扫描量当作实际传输字节数，也不能把 `accepted` 当作角色/舰队已经到达。

## 自动检查与可复现命令

新增 `src/Core/GroundCaptureMetrics.cs` 作为纯逻辑计数/时间桶；`src/Game/NativeGroundCaptureProfile.cs` 作为原生地表观测器；`tools/OptimizationChecks/GroundCaptureChecks.cs` 覆盖分段标签、计数、直方桶上界、负数拒绝及清理；`tools/Analyze-MultiplayerDiagnostics.ps1` 能解析新的 `[profile]` 阶段与 `[ground-counts]`。

```powershell
dotnet run --project .\tools\OptimizationChecks\OptimizationChecks.csproj -c Release

$pwsh = "$env:LOCALAPPDATA\CatStudio\FreeWorldMultiplayer\DevTools\PowerShell\7.5.4\pwsh.exe"
& $pwsh -NoProfile -File .\tools\Analyze-MultiplayerDiagnostics.ps1 -SelfTest

# 只打三端正式包，不更改已安装游戏
& $pwsh -NoProfile -File .\Sync-ModCopies.ps1 -Target All -BuildOnly
```

在用户实际完成房主/客人同场复测后，`Analyze-MultiplayerDiagnostics.ps1` 可使用两份日志生成汇总，区分地表时间桶与扫描/变更计数。收集真实数据前，不判定格子扫描、实体字段还是原生地图装载为最慢阶段。
