# 续开联机世界失败修复 · 2026-10-19

任务：`resume-world-message-recorder-20261019`。修复版本：V1.36。

## 证据与修改

TapTap 诊断日志 `20261019-064332.943Z-pid443832-481e8570f9e54836b003d250f872d7a3.log` 第 1392 行起记录了北京时间 14:44:35 的续开失败：`HostLoad → GameBridge.LoadWorld → NativeWire.Unpack → MessageRecorder..ctor → update → UserBean.getTime` 抛出空引用。读取快照发生在 `ActivateLocal` 安装已恢复游戏数据之前；原版构造函数读取 `gameData.getElapsedMM()`，而消息记录对象尚处于脱离游戏的恢复阶段。

MOD 新增 `NativeArchiveCreation`，只对精确 `MessageRecorder` 类型配置不执行构造函数的对象创建，清空构造参数契约，由既有字段契约还原 `starMapId`、`recordTime`、`tag`。`NativeWire.NativeFieldsResolver` 接入该配置；类型白名单和其余对象恢复规则保持原逻辑。无需删除或转换存档，不替换游戏程序集。

子 Agent 使用现有 Mono.Cecil 静态读取 Steam/TapTap 自带程序集：两端均保留该记录类型的三个 public 字段，以及 `FormatterServices.GetUninitializedObject(Type)` 的实际方法体。此为元数据证据，不是游戏运行验证。
