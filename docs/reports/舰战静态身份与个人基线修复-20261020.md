# 舰战静态身份与个人基线修复

## 用户现象与证据

用户报告联机进入战场直接卡死，提供两条 guest 日志：

- `CapturePlayerBattleScene` 抛出“原生战场静态对象存在重复层级身份”，沿 `CapturePlayerFleetBattle`、`TickPlayerFleetBattles` 进入战斗失败处理。
- `personal.apply-delta` 收到另一玩家的 `ET_LuaRecords` 更新，`ValidatePersonal` 抛出 `Personal field baseline mismatch`。这是远端玩家记录，不是日志中本机 PlayerId。

只读原版 `Battle_Env_Default.prefab` 可找到重复名称 `Stone_1`、`rockA2`。旧代码将纯名称路径当作唯一身份，并用 `Transform.Find` 在接收端解析；合法同名兄弟会冲突，单独删除异常判断仍会选错节点。

个人同步的确定代码缺口：完整世界恢复后没有在原生激活前建立所有玩家的字段确认基线；校验只比较可能受到本机原生回调影响的 live Bean；单独 `personal` 接收没有连续版本门禁。原日志没有字段旧值或原生回调轨迹，不能确认当时是哪条回调改变了 `ET_LuaRecords`，也没有实机证据证明两条异常覆盖所有卡死原因。

## 改动

1. 战场地址统一为转义节点名与同名兄弟序号，组件身份包含 Kind 与组件序号；捕获、校验、接收、真实模板恢复使用同一规则。地址绑定当前战场根并保留已删除节点槽位，避免战中移除让其他节点身份漂移。真实重复或模板缺失继续拒绝；旧名称检查点仅在无歧义时读取。
2. 世界加载先建立已确认个人字段影子，再激活原生上下文。仅 guest 在没有本机地表模拟权时，可按同 PlayerId、同对象、同精确版本和已确认 Before 恢复远端显示副本。本机、房主、地图模拟者、未确认本机采集或真正的 Before 冲突仍严格拒绝。增量仅更新收到的字段，不将未确认字段重新记成权威基线。
3. `personal` 接收拒绝未知玩家与非连续版本，忽略已确认的旧消息，防止回退 PersonalRevision；写入前继续二次检查对象、版本、权限和字段。

战场快照地址格式变化，联机协议从 11 升为 12，双方须使用本轮同版 MOD。玩家资产与存档结构不变；没有修改游戏本体、Project3 源码、共享 Harmony 或运行副本。
