# 退出房间生命周期修复 · 2026-10-20

## 问题与证据

用户退出联机房间后，GameRoot、远征、人员列表、任务和通知更新连续出现空引用。

- GameRoot.Update 访问 curStarMap.starMapInfo；HeroList 访问 gameData.heroTeams；远征访问 gameData.getMothershipStarMapInfo；任务访问 gameData.missions；通知访问 gameData.messageStore。
- Session.CompleteDisconnect 在会话推进中直接释放 GameBridge。旧 Dispose 随后恢复进入联机前的 gameData/curStarMap；从封面进入时二者可以为空，但原生地表和 HUD 尚未清场。
- 房间面板 Leave 直接 CloseSession，并未必然返回封面。即使原生退出已排队，backCover/enterCover 的异步清场也晚于恢复世界引用，存在旧场景更新空数据的窗口。

静态证据支持上述生命周期缺口；没有启动游戏重现，不声称已通过实际双端回归。

## 修复边界

最终检查点和原有退出保存流程不变。在恢复旧世界上下文前清理联机场景；已经进入世界的会话关闭后统一返回原生主菜单，保留原生回调、被动客人的房主离开提示和客人返回桌面路径。只修改本 MOD。

- NativeRoomExit.cs 先确认当前原生数据确属本桥接，关闭地图就绪状态和游戏对话框、地表/银河展示；保留共享 Canvas、dispatcher 与 MOD runtime，让原生封面加载继续推进。
- GameBridge.Dispose 在恢复旧上下文前接入上述收口；Entry 根据保留的 RequiresMenuReturn 覆盖主动与被动结束。切换房间的待执行操作等待封面完成后继续。
- 两份生产源码原有大量历史 dirty，本轮精确暂存退出接线；HEAD 尚缺其他 Owner 的上下文所有权重构，提交版调用使用等效 Active == this 守卫，不整体提交旧重构。构建使用实际工作树版本。

语言缺键警告独立：BaseDefMethod.QCName 已翻译并加品质颜色，MapHoverInfoContent.AddBuild/AddLayer 再调用 getTextByID，形成 id_<color=...>中文</color>。未发现 MOD 覆写名称的证据，本轮不扩改只读本体，不吞掉缺键日志。
