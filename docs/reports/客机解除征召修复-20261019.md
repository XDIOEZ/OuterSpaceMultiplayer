# 客机无法解除征召修复 · V1.40

用户报告：客机开启征召后无法关闭。截图版本 V1.39；预期本人雇员可反复开启和解除征召，按钮、人员标记和实际模式一致。

## 原因与改动

- `GameHooks.ConscriptPrefix` 已按操作发送 `Manual=true/false`，但 `GameBridge.ExecuteNative` 固定调用 `order_Fight_Conscript(actor,true)`，解除请求被执行成再次开启。现改为读取 `payload.Value<bool>("Manual")`。
- 运行时征召模式位于 `AI_BaseFight`，并不在雇员 Bean 中；原有地表 Pose 只传位置和动画。现增可空 `FightActive` / `FightManual`，采集与差量比较均包含它们。非模拟端直接投影战斗模式与 AI 显示引用，跳过 `setRunAI` / `doFightMode` 等任务生命周期，不开启本地 AI 模拟。
- 只改本 MOD，不改游戏本体、雇员归属、命令权限、协议号或存档格式。既有未提交代码全部保留。

## 构建与安装

按用户“后续统一安装”，本轮未安装、未停止游戏、未执行测试或运行验收。

执行 `Sync-ModCopies.ps1 -BuildOnly`：P3 编译打包完成，保留三项既有 CS0649 警告；Steam 经过编译器后，脚本检测到并行反馈 UI 的四份 Entry 源码变化，按保护规则停止。随后收到对方尚需补齐 VisualTheme 的交接，故本轮不重试。没有三端一致构建或 TapTap 完成结果；P3 中间包不能当作统一交付。原始回执保存在 `artifacts/guest-conscript-20261019/build-attempt.json`，等待后续各功能闭合后统一构建安装。
