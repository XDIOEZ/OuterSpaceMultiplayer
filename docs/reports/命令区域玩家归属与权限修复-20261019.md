# 命令与区域玩家归属修复 · V1.49

用户要求 A 的命令不能被 B 取消；命令、区域都带稳定玩家 ID，供雇员识别。友好协作仍按现行 V1 保留，不把协助工作等同于编辑他人的命令。

## 原因与改动

- 原 `ValidateGroundPlanMutation` 用友好合作条件判断能否编辑，导致友好玩家可删除或修改对方计划。现在编辑/取消要求作者一致；原生计划预览删除、修改及候选选取入口也按作者过滤，执行模拟端再次核验。自动完成和原生生命周期保留原语义。
- 原区域创建、扩张、缩减、按层/类型擦除及删除缺少对应网络命令。新 `NativeGroundZones` 在原生区域操作改变地图前捕获意图，通过已有命令管道交给模拟者执行；区域设置及整理操作一起检查作者，批量擦除仅作用本人区域，相邻合并也只合并本人区域。
- 计划和区域复用既有 `EntityOwners[uid] = PlayerId`。新对象在真实插入边界登记作者；快照、差量、房主保存和重新加载沿既有所有权管道保存。旧档未登记对象仅回退地图主人，不以当前操作者补领归属；无原始作者记录的旧数据无法可靠追溯历史创建者。
- 雇员实际计划执行、种植候选、仓储选点、仓储候选及搬运目标读取对应计划/区域作者：本人可做，友好可协助，中立和敌对不替他人工作。不会改变雇员本人的玩家归属。
- 模拟端替访客创建的计划与区域，作者保持访客；新计划正式 UID 由模拟端分配。房主提前归属登记允许当前地图内的已知玩家，同时保留当前会话 UID 号段、地图模拟者和任期核验。
- 网络协议升为 9，双方必须一起更新，避免旧模拟端继续放行旧权限。存档继续使用原所有权结构。

## 范围与交付

仅修改本 MOD；Project3 本体源码、Steam/TapTap 本体程序集及其他 MOD 保持只读。完整本轮工作树窄补丁保存在 `docs/patches/command-region-ownership-20261019.patch`，原有未提交改动保留。

由主控在源码冻结后统一编译打包；游戏运行中的安装由保护规则阻止。未启动游戏、Play Mode 或自动测试，打包安装实际结果见本轮交付回执。

## 用户验收

双方更新后，分别发布命令和区域，测试本人修改/取消、另一玩家框选取消、区域设置/扩缩/批量擦除、相邻区域合并；友好时允许协助工作但仍不允许编辑他人命令，转为中立/敌对后停止协作。交换模拟者并重连/续档，确认作者和限制仍保留；重复点击及任务自动完成不得遗留重复计划或失去同步。
