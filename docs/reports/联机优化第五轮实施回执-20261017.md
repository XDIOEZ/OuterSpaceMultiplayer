## 2. 如何复现（不会安装或启动游戏）

从唯一主仓库运行：

```powershell
$pwsh = "$env:LOCALAPPDATA\CatStudio\FreeWorldMultiplayer\DevTools\PowerShell\7.5.4\pwsh.exe"

# 当前工作树构建输入及 Git 归属状态：写入被 Git 忽略的 artifacts/
& $pwsh -NoProfile -File .\tools\Audit-SourceClosure.ps1 -ReportPath .\artifacts\optimization-f5\final-audit.json

# 目标目录只允许首次创建；再次复测同一指纹时改为验证，不覆盖旧冻结源码
$audit = Get-Content .\artifacts\optimization-f5\final-audit.json -Raw | ConvertFrom-Json
$frozen = Join-Path (Get-Location).Path ("artifacts\optimization-frozen-source\" + $audit.InputDigestSha256)
if (Test-Path $frozen) {
    & $pwsh -NoProfile -File .\tools\Export-FrozenSourceSnapshot.ps1 -AuditPath .\artifacts\optimization-f5\final-audit.json -VerifyOnly
} else {
    & $pwsh -NoProfile -File .\tools\Export-FrozenSourceSnapshot.ps1 -AuditPath .\artifacts\optimization-f5\final-audit.json
}

# 只在冻结源码副本中启动原有三端 BuildOnly。目录名来自本次审计的实际指纹。
& $pwsh -NoProfile -File (Join-Path $frozen "Sync-ModCopies.ps1") -Target All -BuildOnly

# 同时验证源文件、回执、三个 ZIP 里的 BUILD-INFO 和主 DLL 字节
& $pwsh -NoProfile -File .\tools\Verify-FrozenSourceBuild.ps1 -AuditPath .\artifacts\optimization-f5\final-audit.json

# 未完成 Git 归属交接前，这条严格发布检查必须拒绝，不得改成“成功”
& $pwsh -NoProfile -File .\tools\Verify-FrozenSourceBuild.ps1 -AuditPath .\artifacts\optimization-f5\final-audit.json -RequireReleaseClosure
```

工具保留原本的 Project3、Steam、TapTap **真实游戏程序集**与各自 Harmony 引用，不创建第二套构建架构；`-BuildOnly` 不向游戏安装目录复制 DLL。压缩包与报告保留在主仓库的忽略目录 `artifacts/` 内，不进入 Git。

## 3. 双端日志的证据质量

```powershell
# 纯逻辑检查和分析器自检
dotnet run --project .\tools\OptimizationChecks\OptimizationChecks.csproj -c Release
& $pwsh -NoProfile -File .\tools\Analyze-MultiplayerDiagnostics.ps1 -SelfTest

# 用户在真正的双端游戏复现后再指定同一轮房主/客人日志
& $pwsh -NoProfile -File .\tools\Analyze-MultiplayerDiagnostics.ps1 -HostLog '房主日志路径' -GuestLog '客人日志路径' -OutFile .\artifacts\optimization-f5\paired.json
```

现在的解析报告包含 `PairEvidence` 和 `MissingEvidence`。对两端声明不一致的版本直接拒绝；即使声明的版本一致，也**不能单靠日志标题证明 SourceRevision 或同一个房间会话完全一致**，必须再由用户核对真实加载包和操作时间。`client.result=accepted` 只代表命令确认，不能证明舰队物理位置真的移动。

最后一次已有 Steam/TapTap 历史日志没有新的 `[fleet-command]` 和 `[profile]`/`[ground-counts]`：此工具只能合理地报告证据不足；不能用旧慢日志算新版 P95，更不能声称舰队移动故障已经修好。

本轮读取这两份旧日志时，它们声明的 MOD 版本同为 `V1.19`，但报告明确显示 `SourceRevisionVerified=false`、`SameRoomSessionVerified=false`、`FleetCommandsSeen=0`、`ProfileWindows=0`，并生成 3 项缺失证据提示。不能把“同版本”自动推导为“同一份已加载 DLL”。
