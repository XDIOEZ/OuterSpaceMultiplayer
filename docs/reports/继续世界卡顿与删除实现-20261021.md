# 继续世界卡顿与联机世界删除（2026-10-21）

## 问题与证据

用户在 V1.62 报告点击“继续世界”明显卡顿，截图显示 33 个世界。开工源码中 `ContinueWorldMode` 先同步调用 `RefreshWorlds`，再切页；`RefreshWorlds` 调用 `SaveStore.ListWorlds`，每个世界执行完整 `Load`，计算代文件 SHA256，并反序列化 `WorldState`，最后才构建列表。

只读磁盘元数据统计：当前 34 个世界目录、68 个代文件，总代文件约 1282.2 MiB，最大一代约 30.8 MiB；34 个当前主代合计约 631.1 MiB。这说明旧链路可能在一次列表打开中读取、校验并解析数百 MiB。此为静态调用链与文件规模证据，不是 Unity 帧耗时、实机复现或前后性能对比。

## 实现范围

- 继续页立即展示，目录在后台只读取小型指针、名称、代次和时间等元数据；不在打开列表时加载所有世界正文。
- 当前所选世界在后台运行原有完整 `Load` 校验，通过后才能显示“可继续”并续开；未校验与损坏分别显示。真实开房仍完整加载，不将摘要替代权威存档。
- 后台结果仅回到主线程应用；切换选择、刷新、离开或关闭面板后忽略旧结果，限制完整校验并发，避免快速点击创建大量大档解析任务。
- 删除所选世界需要确认名称、时间及世界ID。功能采用从 `worlds` 移入 `deleted-worlds` 的可恢复移除；保留该世界所有代文件，不永久清空磁盘，也不删除身份、设置、单机或其他世界。
- 删除前复核目录身份及状态，限制规范 UID 和根目录范围，拒绝重解析路径；协调保存/加载/删除的存储访问，避免意外保存重新创建已删除世界。
- 只在离线且没有启动/关闭流程时允许删除；删除期间同时拦住按钮及实际 Runtime 启动入口，包括邀请触发的加入。开发过程不对任何真实世界执行删除。

## 可恢复删除说明

文件回收位置为本 MOD 数据根下的 `deleted-worlds/{WorldId}/{UTC时间-随机值}`，在本机通常是 `C:\Users\CatStudio\AppData\Local\CatStudio\FreeWorldMultiplayer\deleted-worlds`。回收不会自动清空，也不立即释放这些文件占用的磁盘空间。世界 ID 容器同时作为防陈旧世界重新保存的标记；手动恢复需先退出所有游戏实例，将保存文件夹移回 `worlds/{WorldId}` 并移除对应空标记容器。本轮没有新增恢复按钮，也没有实际删除或移动用户世界。
