# 舰战入场配置与双方准备 · 2026-10-20

## 问题与静态证据

用户在安排好参战舰船后进入战场，附件报告 `BattleSpawner.SpawnAllFleets: battleField Id 0 is null`。同份日志的 DamagePopup CanvasRenderer、Navmesh 和旧流派适配条目是另外的警告，未据此删除本体组件或修改本体资源。

只读追踪 Project3 源码及当前配置发现：

- `BattleSpawner.SpawnAllFleets` 的双舰队 Bean 分支实际查询 `G_BattleField.getDataID("1")`，报错文字却写 0；查询失败会直接返回，双方 FleetData 保持为空。
- `StandardBattleRule.GetFieldConfig` 使用配置 0；`BattleManager.InitializeBattleData` 先调用 Spawner，再把双方 FleetData 交给规则并构建环境，因此环境可以继续创建，但舰队数据已经缺失。
- 当前 `Assets/StreamingAssets/def/G_Battlefield.fwr` 为 803 字节、9 列 8 行；ID 为 `0, 2, 3, 10, 11, 100, 101, 102`，无 ID 1。ID 0 是 300 × 300 的默认战场。该读取是静态证据，不代表运行中的配置表已被重新加载。
- 既有 `HostBattleConfiguration` 已要求双方配置齐全才能设置 `SceneAuthorized`，没有发现单方配置直接授权的代码缺口；界面仍显示“开始战斗”，且本方确认后即被 MOD 关闭，无法清楚表达等待对方。

## 本轮修改

- 联机玩家舰战通过原版标准规则获取实际战场配置；创建场景前检查配置和尺寸，准备页在预检成功后统一关闭。
- 仅在本 MOD 当前玩家舰战中替换旧 Spawner 的舰队数据初始化，继续使用原生舰队转换、位置算法、规则、部署和生成链。缺少真实配置或双方真实舰队时仍明确失败，不创建假成功状态。
- 原生部署页按钮改为“准备”，本方确认后保留“已准备，等待对方”；双方确认后才进入战场。未收到房主确认时可以手动重发同一部署快照；已提交的舰船和座驾不能继续改动，关闭仍可取消本次战斗。
- 按用户追加要求补充 `[FreeWorldMultiplayer][fleet-battle]` 日志，关联准备、房主配置确认、双方授权和场景初始化，记录战斗身份、任期、双方舰队及状态。日志仅记录关键操作和状态变化，不逐帧输出舰船状态或完整网络数据。
- 未新增第二套 Ready 状态或协议字段；继续使用房主权威的双方配置门禁。游戏本体、原生配置和三个运行副本保持只读。

## 日志定位

日志统一搜索 `[FreeWorldMultiplayer][fleet-battle]`，用 `battleId + epoch` 关联同场记录：

| phase | 用途 |
| --- | --- |
| `preparation.ui.*` | 本端打开、点击、重试、等待房主、等待对方及关闭 |
| `preparation.host.*` | 房主接收、验证、重复、拒绝及保存后授权 |
| `field.preflight` | 标准规则选择的实际战场 ID、宽高或缺配置原因 |
| `spawner.*` | 双方真实舰队初始化数量、缺失的一方及失败步骤 |
| `entry.*` | 请求入场、场景加载、首次就绪或失败阶段 |

共享日志缓存最多保留 512 个阶段键，相同状态不重复输出；异常类型和受控元数据辅助原始错误回执，不吞掉原始异常。完整配置 JSON、网络原文和口令不进入这组新增日志。
