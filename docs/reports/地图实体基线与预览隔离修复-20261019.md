# 地图实体基线与预览隔离修复 · V1.48

用户报告 `NativeMapReplicator.Validate` 抛出 `Entity mutation baseline mismatch`，由 `GameBridge.ApplyMapUpdate` 返回“合并权威地图实时变动”错误。

## 证据与修复

- 该异常检查的是实体存在性：新增时已有实体，或更新/删除时实体缺失；不等于地图修订号不连续。现有错误没有集合或实体标识，无法仅凭用户堆栈确认本次是哪一个实体。
- 原版 `CoreHandle_Plan` 在取消计划预览时就从真实 `spread.plans` 移除计划，清空预览才恢复；修改预览另保留修改前的 Bean。快照、差量采集和入站预校验此前直接读取临时集合。
- 新 `NativeMapPlanBaseline` 从原生缓存重建逻辑上已确认的计划视图，供完整快照、差量、归属采集和只读预校验使用。只有完整事务通过预校验、进入应用阶段且涉及计划时，才清理原生预览；随后按 UID 重新绑定真实计划对象，防止以后取消预览复活已被权威删除的旧计划。
- 原版物品、矿物、植物和容器显示删除会调用 `Stub_PlanRemove` 产生计划变更。新 `NativeMapProjectionGuard` 将这些业务回调限制在权威模拟链，网络投影仍更新原生场景对象与计划显示；原生计划删除内部的附带自动计划也在投影范围内隔离。
- 保留严格实体存在性、身份、修订及任期检查。异常补充 map、collection、identity、operation、present、base/current/target、epoch 和 commit，避免遇到其他类型偏离时仍无法定位；不记录完整 Bean 或身份凭证。

以上为源码证据支持的缺陷修复，未进行双端复现，不能据此断言用户这次错误的具体冲突实体或所有基线偏离来源均已解决。

## 用户验收

双方更新后，在同图反复框选、预览取消/修改计划，同时让另一端完成工作、搬运和删除物品；确认地图持续同步，取消预览不复活已完成/取消的计划。如仍报错，保留新错误中 collection、identity、operation 与修订信息，以定位另一种偏离。
