## 五、R13-04 · P0 舰队无法移动：找第一个失败阶段

使用已有 `FleetCommandTrace`、`NativeFleetMotionEvidence`，客人通过原版 UI 操作**自己的**舰队，同星系、跨星系各一次；房主舰队作对照。按同一 `CommandId` 关联：

`native.hook/route → session.submit → client.sent → host.received → host.native.begin/end → host.motion.armed → host.motion → client.result`。

| 断点 | 优先责任文件 | 真实验收 |
| --- | --- | --- |
| 点击原版入口但无 `client.sent` | `src/Game/NativeGalaxy.cs` 的 `RouteFleetCommand`、原生导航 Hook，`src/Session/Commands.cs` | 证明原版命令确实进 MOD，合法拒绝携带明确原因 |
| 房主收到但没有完成原生命令 | `src/Session/Networking.cs` 与 `Commands.cs`、`src/Game/NativeGalaxy.cs` | `host.native.end` 的 accepted/rejected 结果与权限、暂停/战斗锁一致 |
| 房主 accepted，但采样窗口未见位置变化 | `NativeGalaxy.TickPlayerFleets` / 原版运动调用 | 实际观察房主原生舰队位置；`unchanged-after-120-host-ticks` 是 120 次采样，不是 120 秒、更不自动代表 BUG |
| 房主真实移动但客端看不到 | 已入库的 `NativeFleetSynchronization.cs`、`NativeRemoteFleetProxy.cs` 和 Galaxy 投影路径 | 保持唯一 UID，不生成另一份真实舰队/AI，展示与房主位置一致 |

**只修首个证实的故障点**；没必要时不动传输、协议、2D 地图或舰队动力学。房主/客人实际舰队都要在暂停、战斗锁、离线冻结、重连后复测；不得把 `ACK=accepted` 当成“已移动/已抵达”。

## 六、R13-05 · P0 2D 热点实验与 R13-06 · P1 单点优化

在相同世界、硬件、网络、地图格数、实体/建筑/动物规模及 2～4 人下，实际开启 `FWM_PROFILE=1`，收集**至少三轮**基线数据：

| 真实 2D 场景 | 使用现有阶段/指标 | 结果必须包含 |
| --- | --- | --- |
| 冷图、热图、坏缓存重试 | `map.cache.encode/reassemble/apply`、`transport.handle` | 地图加载实际可见耗时、缺块/内容字节、完整 SHA、native ready 和可靠 FIFO 是否正常 |
| 双人同一地块采集/建造/战斗 | `ground.capture.entities/fields/tiles/poses/personal`、`[ground-counts]` | 房主/客人 P95 桶上界、扫描与变更数量、工作/伤害/库存/角色 UID 是否真实同步 |
| 太空运动、跨图、保存与重连 | `galaxy.broadcast`、`world.save`、`[fleet-command]` | 主机实际运动/客端真实显示、队列峰值、`SaveGeneration` 完整且不重复结算 |

只有真正的双端日志、明确同房场景、可合并 `histV=1` 14 桶和每轮有效采样数才允许计算 P95；`slow-operation` 只能证明发生过慢事件，`ground-counts` 扫描量不能伪装成真实网络传输字节。

**R13-06 最小补丁仅择一**：

- 如果 `tiles` 是最大热点，先确认每个原生改格入口都能被发现，否则仍要保留 `string[,]` 全图比较。
- 如果 `entities/fields` 是热点，考虑复用已经确认未变的编码/字段缓存，但角色、装备、资源、归属和任务必须仍由真实模拟产生。
- 如果 `poses` 是热点，只优化 2D 远端显示与采样，客户端不能成为第二个原生 AI 模拟者。
- 如果 `cache/transport/world.save` 最大，定位反复解析/复制/不必要分配，不能跳过地图整事务 SHA、`IsMapReady`、ACK 或完整存档代。

以**最小文件范围 + 原 Owner 单独提交 + 可恢复旧包**交付；用现有 [六轮性能对照工具](联机第八轮性能实测使用说明.md) 的 `Compare-MultiplayerPerformance.ps1` 计算**三轮旧 + 三轮新**合并直方桶 P95。目标环节 P95 至少下降 **25%**，其他关键环节不恶化超过 **10%**，且资产/存档/单模拟者正确。**以上是目标，不是现在已实现的收益**。
