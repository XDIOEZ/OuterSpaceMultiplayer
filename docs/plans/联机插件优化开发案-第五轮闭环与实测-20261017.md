### 目标与不可改变的契约

1. **正确性 P0**：房主唯一世界权威，同一 2D 地块一个有效模拟者；`AuthorityEpoch + Revision + CommitId`、UID/玩家归属、ACK、`TransferId`、完整 `SaveGeneration` 不因性能改动失效。
2. **可观测 P0**：能回答“点了舰队移动后具体卡在哪一环”和“地表到底慢在实体、字段、格子、位姿、加载还是网络”。
3. **性能 P1**：选定热点的同条件 P95 建议目标下降 **≥25%**，其它关键操作 P95 不恶化 **>10%**；这是**未来验收目标**，不是已经取得的结果。
4. **可回退 P0**：用户单机存档隔离、首次资产不重复、离线舰队冻结、原版地表任务/动作、战果和战利品一次结算均与 V1 保持一致。

## 2. 开发顺序和任务卡

依赖链：**F5-00 源码闭包 → F5-01 三端正式包 → F5-02 双端取证 → 只选择一个实测热点 F5-03/04/05 → F5-06 验收**。未通过 F5-00 时允许只读排查、纯逻辑测试或内部 `BuildOnly`，不把包称作“已通过发行验收”。

| 任务 | 优先级 / 责任 | 实施动作 | 放行证据 |
| --- | --- | --- | --- |
| **F5-00 源码归属与闭包** | **P0 / 主控 + Core/Session/Game 各原文件负责人** | 使用 `tools/Audit-SourceClosure.ps1` 清点全部输入；优先处理未跟踪的 `src/Core/MapSnapshotDeltaCodec.cs`、`src/Session/MapSnapshotCache.cs`、`src/Session/MapViewLoading.cs` 及混合修改的 `src/Game/NativeMapReplicator.cs`。逐文件对照作者、接口、依赖与原始改动，再按单项任务选择性提交 | `-RequireGitClosure` 通过；干净检出的源码能构建出同等接口、同一 `SourceRevision`。**禁止 `git add -A`、`reset`、`clean` 或覆盖他人改动** |
| **F5-01 三端正式编译包** | **P0 / 主控** | 在源码收口后执行 `Sync-ModCopies.ps1 -Target All -BuildOnly`；逐个核对 Project3、Steam、TapTap 各自真实程序集、Harmony 提供者、`BUILD-INFO.json`、版本与指纹 | `Completed=true`、`BuildOnly=true`、`Installations=[]`；三个 `ReferenceMode` 正确、`SourceRevision` 相同。编译、打包和**实际安装**分别记录 |
| **F5-02 双端复现与性能采样** | **P0 / Session 观测 + Game 调用链 + 用户实际游戏操作** | 双人同一 `SourceRevision` 运行，客人移动自己的舰队，房主同时采样。分别进行冷图、热图、同图角色工作/建造、跨图、保存、掉线重连；条件允许再增加 3～4 人。每场景至少 **3 次** | 每次标注玩家人数、地图规模、网络通道、角色/建筑数量，保留房主/客人的 `[fleet-command]`、`[profile]`、`[ground-counts]` 和实际画面/操作结果 |
| **F5-03 2D 实体与位姿热点** | **P1 / Game，选中时才认领** | 如 `ground.capture.entities` 或 `poses` 最慢，再深入 `NativeMapReplicator.CaptureUpdate`、`NativeWire.CaptureValue` 和角色位置/动画读取。优先减少同一确认基线的重复反射/编码；远端表现可考虑**只作用于画面**的位置平滑 | 角色 UID、目标、动画、工作、攻击与倒地正确；单图唯一模拟、真实资产无复制；优化前后实体数相同且 P95 有可核验改善 |
| **F5-04 2D 格子与地块加载热点** | **P1 / Game 地形 + Session FIFO/Core 缓存，选中时才认领** | 如 `tiles` 或 `map.cache.apply/reassemble` 最慢，再调查 `string[,]` 扫描、SEED 块编码、`StageNetworkMapView`、`TickMapLoading`。只有证明原生所有地形变更入口被覆盖，才考虑“脏格子索引”；否则坚持全图比较 | 冷/热/坏缓存与断线中断能恢复；hash/SEED 校验、`Revision`、可靠 FIFO、原生 ready/真实角色投影不被绕开；不能跨帧应用半条原生地图事务 |
| **F5-05 传输/舰队/保存热点** | **P1/P2 / Transport 或 Session/Core，三者择其真实热点** | 若耗时集中 `transport.handle`，先分开协议解码和业务调用；若 `galaxy.broadcast` 慢，再看重复采样与字段编码；若 `world.save` 慢，再确认完整代捕获与写盘成本。**不靠随意降频、提高内存上限或跳过 ACK 来“提速”** | Steam/TCP 终止与 ACK 不丢；舰队离线冻结、在线全队可见；`active.json` 原子提交及上一完整代可恢复 |
| **F5-06 回归与发布门禁** | **P0 / 主控收口 + 用户实机验证** | 运行纯逻辑检查、三端构建、包指纹核验，按下文矩阵做多人实测；通过后才依仓库规则考虑同步到三个 `mods\FreeWorldMultiplayer` 副本 | 分别标注**代码/逻辑检查/编译/正式打包/安装/游戏验收**六项结果；任一关键正确性回归都要回退所选小补丁 |

**任务分工要求**：同一时段每份混合源码只有一个明确负责人。Game 维护原生捕获与画面；Session/Core 维护权威事务、加载队列与存档；Transport 只管理字节和队列；Entry 只展示真实状态。任何跨模块签名先在 [AGENT-COORDINATION.md](../../AGENT-COORDINATION.md) 记录，主控负责整合、评审与独立 Git 提交，**不能抢占他人尚未交接的混合文件**。

## 3. 现场数据采集说明（F5-02）

### 开启诊断

本次计划沿用已有功能，**不重新开发日志框架**。在启动实际游戏进程前设置环境变量 `FWM_PROFILE=1`，或给启动参数加 `-fwm-profile`。两端都应使用**相同的 MOD 源码指纹**，并记录是 Steam、TapTap 还是 IP 直连。

```powershell
# 下列命令在 FreeWorldMultiplayer 主仓库中执行。
$pwsh = "$env:LOCALAPPDATA\CatStudio\FreeWorldMultiplayer\DevTools\PowerShell\7.5.4\pwsh.exe"

# 查看工作树是否能完整从 Git 复现（当前仍会报告不完整）
& $pwsh -NoProfile -File .\tools\Audit-SourceClosure.ps1 -RequireGitClosure

# 静态回归，不启动游戏
dotnet run --project .\tools\OptimizationChecks\OptimizationChecks.csproj -c Release
& $pwsh -NoProfile -File .\tools\Analyze-MultiplayerDiagnostics.ps1 -SelfTest

# 通过源码和环境门禁后，仅生成三端正式包
& $pwsh -NoProfile -File .\Sync-ModCopies.ps1 -Target All -BuildOnly

# 双端实机运行后才使用本分析器：
& $pwsh -NoProfile -File .\tools\Analyze-MultiplayerDiagnostics.ps1 -HostLog '房主本轮日志完整路径' -GuestLog '客人本轮日志完整路径' -OutFile .\artifacts\optimization-diagnostics\paired-run.json
```

### 如何判断热点

| 新日志证据 | 接下来的判断 |
| --- | --- |
| `ground.capture.entities` P95 高，`entitiesScanned` 远多于 `entityChanges` | 先调查实体字段扫描/编码能否安全复用；不能因此跳过任务、所有权、状态变更 |
| `ground.capture.tiles` P95 高，`tilesScanned` 大、`tileChanges` 少 | 考察完整网格扫描的成本；没证明所有修改入口可观察前，**不直接改为仅发送“脏格子”** |
| `ground.capture.poses` 高，`posesSampled` 多、`poseChanges` 少 | 把真实动画、攻击与目标字段保留在变更判断中，必要时只优化远端显示差量 |
| `map.cache.reassemble/apply` 或 `transport.handle` 高 | 先确定耗时在块校验、原生地图恢复、实体投影还是业务调度；不能把大消息毫无证据地归咎于带宽 |
| `client.sent` 没有对应 `host.received` | 对照相同 `CommandId` 检查 Session/Transport；日志缺失本身也可能是采样/旧包，不立刻断定丢包 |
| `host.result=accepted`、`client.result=accepted`，但舰队坐标不动 | 继续核对房主原生运动/锁定/帧推进及客端表现；**ACK 不等于位移完成** |

统计口径：`[profile]` 的 P50/P95/P99 是固定直方桶**上界估计**；`[ground-counts]` 的实体、格子、位姿数量是 CPU 扫描与变更量，**不是网络发送字节**。既有 `[slow-operation]` 只记超阈值慢事件，也不能据此计算整体 P95。没有同条件前后比较，只能写“热点待确认”。

| 用例 | 核验内容 | 严重错误/停止条件 |

## 5. 每项任务的交付物与回退策略

每张任务卡都必须附：`Git 源码基线指纹`、问题与复现、输入规模/运行条件、修改前数据、精确文件差异、修改后相同场景数据、逻辑回归、三端 `BUILD-INFO.json`、**安装状态和实机状态**、本地任务提交哈希、回退办法。不得只写“编译成功/目测不卡”。

当来源权限不清、其他 Agent 正在改同一文件、`SourceRevision` 在构建中变化、协议/存档版本不匹配或关键资产一致性失败时，**停止构建安装并保留现场**；不得改写协议来绕过错误或强制结束游戏。BUG 真修复时才按仓库规则处理 `VERSION` 与 `CHANGELOG.md`；本计划文档本身不升版，未经授权不推送远端。
