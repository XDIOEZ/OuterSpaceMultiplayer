### 每个交接批次的强制操作

1. 对照**当轮新鲜** `Audit-SourceClosure.ps1` 的路径、SHA256、`git diff HEAD`，避免与正在修改的其它 Agent 冲突；Owner 在 `AGENT-COORDINATION.md` 写明可交接文件/具体行块、调用方、历史修复和回滚点。
2. 对 U 文件先核依赖和真实接入；对 M 文件逐 hunk 分清此前用户/他人改动与本批次，禁止 `git add -A`、`reset`、`clean`、从运行副本倒灌。没有原 Owner 回复，写**待交接**，不能默认为许可。
3. 每个最小提交只包括已经签收的文件或精确补丁；提交前检查 `git diff --cached --check` 及 staged 文件清单，跑相应测试。出现不相容契约则停在接口方，不补空实现、假成功回执。
4. 每次提交后复算剩余 `UntrackedInputCount` / `ModifiedTrackedInputCount`，说明数量如何变化；没有减少就如实报告。Git 工作区行数不等于构建输入数。

## 五、正确性红线与可复用工具

| V1 不变量 | 回归与立即停止条件 |
| --- | --- |
| 房主权威、2D 地表只由一台电脑真实模拟 | `AuthorityEpoch/Revision/CommitId` 错乱、客户端再次执行地表 AI/生产/伤害、旧任期覆盖或多个模拟者即停止 |
