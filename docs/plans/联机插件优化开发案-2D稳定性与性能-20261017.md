## 2. 目标、不可改变的规则和排序

**用户感知目标**：客人下命令有可靠反馈；多人在同一 2D 地块时，人物/动物、任务动作、建筑和物资连续显示；首次进图与二次进图不出现无解释的长时间停顿；退出、重连、保存之后各人的资产仍正确。

**不可变更的 V1 规则**：房主推进世界及唯一银河权威；同一 2D 地块同一时刻只有一位有效模拟者；客人不得把本地角色、任务和库存作为另一份权威；世界/玩家 `WorldId + PlayerId`、实体 UID、`AuthorityEpoch + Revision + CommitId`、`TransferId`、ACK 和 `SaveGeneration` 必须保序且幂等。离线玩家舰队冻结，首次资源不重领，战果/运输与战利品只结算一次。单机档和联机档隔离。

**建议性能验收线（不是现有实测结果）**：针对已确认的热点，前后同场景 P95 降低 **≥25%**；其他关键操作 P95 不恶化 **>10%**；没有新的长帧、丢消息、重复人物/物品或不一致存档。以实际数据判断，不为达数字而降低同步准确性或原生玩法频率。

执行顺序：**A0 源码闭包 → A1 同源构建 → A2 双端舰队取证和 2D 性能基线 → 选择 B1/B2/B3 的一项最重热点 → C0 完整回归**。A0 未完全通过时可以继续只读分析或内部 `BuildOnly`，但**不得发布为已验证正式版本**。

### A0 · 可复现源码闭包

- **负责人**：主控协调先前 Game/Session/Core/Entry/Transport 的真实文件所有者。
- **位置**：`tools/Audit-SourceClosure.ps1`、`AGENT-COORDINATION.md`、待收口的未跟踪/已修改源文件。
- **动作**：重跑审计并按输入表逐项确认来源、模块所有权、依赖、原始改动和后续维护者。先处理 `src/Core/MapSnapshotDeltaCodec.cs`、`src/Session/MapSnapshotCache.cs`、`src/Session/MapViewLoading.cs`；它们已含既有其他 Agent 功能及先前窄优化，**不能只截取新改动就丢失原始实现**。按各独立任务提交，不使用 `git add -A`、`reset`、`clean` 或整库覆盖。
- **完成证据**：`-RequireGitClosure` 通过，并从对应提交生成独立、可重现的 `SourceRevision`；签名/闭包中的用户存档、凭证和第三方运行时不会被误纳入仓库。遇到归属不明先保留，不强行标记完成。

### A1 · 三端构建门禁

- **负责人**：主控；仅使用主仓库的 `Sync-ModCopies.ps1` 和已经校验的便携 PowerShell 7。
- **动作**：G0 完成后先执行 `-Target All -BuildOnly`。逐项检查 Project3、Steam、TapTap 三套真实游戏/Unity 程序集引用、目标 Harmony 提供者、`BUILD-INFO.json`、版本 `V1.19`（如实际修 BUG 则依仓库规则升版）与同一 `SourceRevision`。
- **完成证据**：三包输出、`Completed=true / BuildOnly=true / Installations=[]`、正确的 `ReferenceMode`、三端一致指纹、无缺失引用。**正式运行副本同步需另行过游戏进程、备份、可回滚和权限检查；不替换 Project3 本体/共享 Harmony**。

### A2 · 双端行为与性能基线

- **负责人**：Session/Transport 观测、Game 原生接入；由用户在游戏中完成实机操作。
- **动作**：在**同一轮**房主与客人日志中按 `CommandId` 对照 `native.hook → native.route → session.submit → client.sent → host.received → host.native.begin/end → host.result → client.result`。命令结果 `accepted` 只证明执行接受，**还要核对主机物理位置和客端画面是否改变**。
- **性能样本**：2 人为最低组；有条件再用 3～4 人。固定同一世界、2D 地块尺寸、地块内角色/动物/建筑数量、游戏版本、网络通道和设备，分别执行冷图、热图、同图 2D 操作、跨图、舰队航行、保存、退出重连，各场景至少 **3 轮**。开启 `FWM_PROFILE=1`，分别收集 ``transport.decode`、`transport.handle`、`maps.publish`、`personal.publish`、`map.cache.encode/reassemble/apply`、`world.save`、`galaxy.broadcast`。
- **完成证据**：双方日志、两端实际游戏结果、CPU 主线程 P50/P95/P99 **桶上界**与最大值、用户感知入图时长、收包队列峰值、实际网络流量和重同步次数。按热点排序后只选一个最有价值的开发卡；未取到有效数据不能宣称卡顿或舰队故障修复。
