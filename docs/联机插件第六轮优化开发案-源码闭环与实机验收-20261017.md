## 一、这次优化的方向

**重点不是再次添加缓存，而是把已有代码变成能从 Git 复现、能在真实双端测量、能明确验收和回滚的联机版本。**

上轮已经完成的部分不要重复开发：`NativeMapReplicator.CaptureUpdate` 的 2D 实体/格子/位姿分段统计、`FWM_PROFILE=1` 计时与数量汇总、可靠 FIFO + 地图 ready 屏障、SEED/内容块缓存、缓存地图减少重复 JSON/缓冲复制、舰队命令阶段日志、按接收者舰队差量与广播编码复用、53 项纯逻辑检查。

**最新可核实基线（本案编写时）**：

**不变量**：房主唯一世界权威；一张 2D 地图只有一个有效模拟者；每人母舰、舰队、资金、雇员、基地独立；`WorldId + PlayerId`、UID、`AuthorityEpoch / Revision / CommitId`、可靠 ACK、`TransferId`、完整 `SaveGeneration` 不受优化影响。离线舰队冻结；地图缓存不是资产权威；单机与联机存档隔离；赠送/袭击/运输与战斗成果只结算一次。不得替换 Project3/Steam/TapTap 本体或共享 Harmony。

## 三、V6-04 按数据决定改哪里

| 实际测到的热点 | 代码入口 | 首选小范围优化与禁止事项 |
| --- | --- | --- |
| 2D 实体/字段捕获最慢 | `Game/NativeMapReplicator.cs`、`Game/NativeWire.cs` | 对比 `entitiesScanned/entityChanges` 与耗时，找重复反射或重复转换；不能跳过任务、伤害、库存和实体 UID 变化 |
| 2D `string[,]` 格子扫描最慢 | `NativeMapReplicator.CaptureUpdate`、`NativeSeedMapCodec.cs` | 先证明全部原生改格入口可追踪，再评估脏格子；否则坚持全图比较。不能让 SEED 代替人物和真实资源 |
| 2D 人物位姿采样最慢或跳动 | `NativeMapReplicator.CaptureUpdate`、`NativeGroundPresentation.cs` | 只优化远端**表现**的采样/平滑，不让投影端跑人物工作、物理和战斗，不跳过动画/目标/倒地变化 |
| 客端地图大事务最慢 | `Session/MapSnapshotCache.cs`、`MapViewLoading.cs`、`Core/MapSnapshotDeltaCodec.cs` | 保留已经存在的 typed FIFO 与一次缓冲；根据实际 `reassemble/apply/handle` 分段寻找剩余重复内存操作，不把单事务拆成半个已应用地图 |
| 客人舰队“命令已确认但不动” | `Game/NativeGalaxy.cs`、`NativeFleetSynchronization.cs`、`Session/Commands.cs`、`Networking.cs` | 先确认房主是否真实移动，再区分原版 Hook、房主锁定、运动状态与客端显示；`accepted` 不是位移完成证据 |
| 网络积压或保存最慢 | `Transport/TransportQueue.cs`、`Session/MultiplayerSession.cs`、`Core/Storage.cs` | 保护 FIFO/ACK、断开消息和 `active.json` 完整代原子切换；不能用增加队列上限或省略持久化确认伪装提速 |

## 四、实际验收矩阵（用户真实运行）

| 场景 | 记录的信息 | 必须保持 |
| --- | --- | --- |
| 房主+客人创建、续开、再次加入 | 世界与 MOD 指纹、`PlayerId` 对应的资产摘要（不公开凭证） | 单机存档不串用，重连不重复生成母舰/雇员或领取资源 |
| 客人同星系/跨星系移动与房主对照 | `CommandId`、是否出现航线、房主物理位置、客户端所见位置、ACK | 只有自己控制己方舰队；暂停/舰战锁明确拒绝；离线不续走航程/耗油 |
| 2D 冷图 → 热图 → 损坏缓存 | 入图可见耗时、`map.cache.*`、`ground.capture.*`、角色和物资数量 | 原生地图 ready 后按序恢复；错误缓存重新取得完整内容，不漏建筑、人物、动物和物资 |
| 2～4 人同图合作、关系变更、模拟者断线 | 格子/实体/位姿扫描量、任务/库存变化、`AuthorityEpoch` | 一个有效模拟者，雇员归属不变；关系变更不双算、不漏真实受伤或建造 |
| 战斗、空投、访客运输、离线袭击 | 守军倒地、袭击时钟、一次撤离/仓容量、前后资产 | 沿用 V1 的 10 分钟袭击、60 分钟冷却与一次性战果/战利品结算 |
| 房主保存、断线退出、杀进程恢复 | 保存代指针、hash、回执、重新进入后状态 | 已确认事务不丢、未落盘不谎报成功，上一完整存档代可恢复 |

每个性能场景须固定**世界、玩家人数、地图格数、实体量、硬件和网络条件**，重复至少 3 次并分别记录房主/客户端。`[profile]` 的 P95 是固定桶上界；`[slow-operation]` 是慢事件抽样，不是完整延迟分布；`[ground-counts]` 是扫描/变化数量，**不是实际网络字节**。

## 五、工具、交付与停止条件

```powershell
# 在唯一主仓库执行。可写入 artifacts 诊断数据，不会修改游戏本体。
$pwsh = "$env:LOCALAPPDATA\CatStudio\FreeWorldMultiplayer\DevTools\PowerShell\7.5.4\pwsh.exe"

# GIT 可追溯的源码闭包：当前仍有历史输入未收口，此项预期不能放行

# 逻辑回归和诊断解析器自检
dotnet run --project .\tools\OptimizationChecks\OptimizationChecks.csproj -c Release
& $pwsh -NoProfile -File .\tools\Analyze-MultiplayerDiagnostics.ps1 -SelfTest

# 真正双端运行后，由用户提供同一轮房主/客人日志路径
& $pwsh -NoProfile -File .\tools\Analyze-MultiplayerDiagnostics.ps1 -HostLog '房主日志完整路径' -GuestLog '客人日志完整路径' -OutFile .\artifacts\optimization-diagnostics\paired-run.json

# 通过源码/版本门禁后，执行官方三端只构建（不安装）
& $pwsh -NoProfile -File .\Sync-ModCopies.ps1 -Target All -BuildOnly
```

每张卡的交付物：负责人和文件归属、复现证据、基线数据、源修订指纹、最小补丁、前后对照、纯逻辑与原生验收、三端包 `BUILD-INFO.json`、本地独立 Git 提交、回退办法。旧工作树冻结工具 `Export-FrozenSourceSnapshot.ps1` 仍可作内部复核，但不能把冻结旧改动当成干净 Git 提交或批准部署。

**严格停止条件**：有人仍占用混合文件；Git 无法完整复现；三端源码指纹不一致；加载中途发生 Revision/ACK 回退；单图出现两个模拟者；资产复制、结算重复或保存代损坏。出现上述任何一项，保持现场，不修改 Project3/Steam/TapTap 本体，不覆盖共享 Harmony，不启动游戏或发布工坊，待定位并回滚对应补丁。
