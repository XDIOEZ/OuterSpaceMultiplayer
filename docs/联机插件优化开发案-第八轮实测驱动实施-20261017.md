## 三、第一轮实机实验怎么做

### 实验 A：舰队不动（先解决正确性）

1. 记录双方当前已加载包的 `SourceRevision`、平台（Steam/TapTap/Project3）及同一次会话标识；为保护隐私只用匿名标签，不复制身份密钥、登录令牌或聊天正文。
2. 客人选择自己的舰队，在原版操作入口发一次航行命令；房主保持同星系观察，确认有无航线以及真实位置变化。重复一次跨星系操作，再做房主舰队对照。
3. 双方启用 `FWM_PROFILE=1`，按 `CommandId` 查 `[fleet-command]` 事件：`host.motion=position-changed` 只表示房主确实移动；`host.motion=unchanged-after-120-host-ticks` 表示该采样窗口未见位移；两者都**不能单独证明客户端画面/回调最终成功**。
4. 暂停/舰战锁、离线冻结与重连分别再测一次：正常拒绝要说明真实原因，舰队 UID、燃料、航程与离线位置不变。

**定位输出**：第一个断点、直接责任文件、最小修复范围、双方回放证据。没有同轮两侧记录时写“缺实机证据”，不猜是 TCP、Steam、房主还是原生运动问题。

### 实验 B：2D 同图和入图卡顿（随后选最高热点）

| 场景 | 操作流程 | 需保留的度量 |
| --- | --- | --- |
| **冷图** | 客人首次进入房主有角色/建筑的地块，等地图和原生角色 fully ready | `transport.decode/handle`、`map.cache.encode/reassemble/apply`、加载可见耗时、实体与格子数量 |
| **热图** | 同一客人退出视野后重进原地块，复用准确缓存 | 实际缺块数、内容字节、校验失败/回全量次数、入图时长及实体是否一致 |
| **2D 双人同图** | 一人真实模拟，另一人参观；做建造、采集、人员运动与战斗观察 | `ground.capture.entities/fields/tiles/poses/personal` 的 P95、`ground-counts` 中扫描与变化量、实际角色/物资同步 |
| **异常流程** | 入图中断线、损坏缓存、暂停与保存恢复 | ready 屏障、FIFO 顺序、ACK、`Revision`/`AuthorityEpoch`、存档完整性与是否卡死 |
| **可选压力组** | 3～4 人逐步进入同图及不同地块 | 同地图模拟者数量、队列峰值、主线程长帧和按玩家字段/位姿数据量 |

**采样口径**：各场景至少 3 轮；记录 `profile` 窗口实际 `count`，不能只截取某一条最坏慢日志。当前工具报告的 P95 是**直方图桶上界**而非精确分位；`ground-counts` 是扫描/变化次数、`map.cache.chunks` 是内容字节，都不能冒充实际网络总流量。不合格样本明确标记剔除原因。

## 四、功能不变量与回归门槛

| 测试项目 | 必须保留 |
| --- | --- |
| 身份和存档 | 联机与单机存档隔离；每位玩家母舰、雇员、舰队、资金、科技独立；重连不重复首次发放 |
| 唯一模拟者 | 一张 2D 地图任何时刻至多一个有效模拟者；接管遵守 `AuthorityEpoch + Revision + CommitId`，非权威机器仅展示或提交意图 |
| 地图恢复 | SEED 只管原版可重建地形；角色、建筑、物资、运输仍按真实权威数据；坏缓存正确回房主，`IsMapReady` 和可靠 FIFO 绝不能提前绕过 |
| 舰队 | 房主推进航行；在线同星系互见所有舰队；离线舰队不可见且冻结、不额外耗油、不复制远端代理资产 |
| 访问/战斗/运输 | 保留玩家关系/访客权限，10 分钟离线袭击、60 分钟冷却、唯一一次一仓撤离，物品与战果仅结算一次 |
| 保存与退出 | `SaveGeneration` 同一完整代，失败时不写虚假成功，`active.json` 原子切换且可以恢复上一完整代 |

**任何一次**角色/物资复制、ACK 漏确认、合法动作被隐藏拒绝、旧任期覆盖、地表双模拟、半代存档被认作成功，立即停止当前优化补丁的发布，保留日志和可回退构建包。禁止通过“只同步快照”、削减地表原生模拟或提高队列上限来掩盖正确性问题。

## 五、开发协作与交付格式

主控负责源码归属、签名边界与独立 Git 提交；Game 只处理原生角色/舰队与 2D 画面；Session/Core 负责事务、个人修订、地图入队、完整存档；Transport 负责可靠字节与背压；Entry 展示真实房间状态和拒绝理由。改动前在 [AGENT-COORDINATION.md](../AGENT-COORDINATION.md) 认领唯一文件范围；对历史未跟踪/混合修改，必须完成实际交接后才可整体提交。

每张任务交付一次可核验记录：**源码指纹 → 复现步骤 → 两端旧数据 → 修改文件与最小差异 → 同条件新数据 → 逻辑/构建/安装/实机分列结果 → 独立 commit → 回滚版本**。纯性能计数、文档、测试工具不擅自升 `VERSION`；确实修复独立 BUG 时才按项目政策升级版本并记 `CHANGELOG.md`。未经单独授权不 `push`、不发布工坊。
