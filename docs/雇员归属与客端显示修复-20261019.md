# 雇员归属与客端显示修复

任务：ground-personnel-20261019。用户提供 V1.33 双端截图；只修改独立联机 MOD，Project3 本体只读。游戏、跨端联机和测试由用户执行。

## 代码证据与修复边界

- 原生 `MainHero_HeroList` / `Top_HeroGrid` 从己方阵营获取人员，没有联机 PlayerId 过滤。联机同图角色保留真实人员对象，故原生己方列表可能同时包含不同玩家的雇员。列表应按真实归属筛选本地玩家，不能直接删除阵营管理器的共享列表成员。
- 原生 `HeroManager.changeHeroAlliance` 会修改人员所属容器、持久阵营和管理器队列，不适合用来创建观察者眼中的敌人代理。真实 UID、玩家归属和已有 `RoleAlliance.isHostileAlliance` 双方关系判断必须保留，敌对外观及选择交互通过本地表现适配。
- 原生 `BaseRole.logic` 调用 `flushSorting`，后者把人物、装备和携带物放入地图渲染层。MOD 非模拟端 `MapUpdatePrefix` 仅运行 `casePaint`，漏掉这一步。Spine 新建 MeshRenderer 没有地图排序层，可能被地面遮挡，而名字 UI 仍可见。修复应补纯表现刷新，不能为了显示而开启第二份角色逻辑、AI 或世界模拟。

以上为源码调用链结论，未通过游戏运行确认。日志中的其他缓存目录与原生 MapManager 异常没有足够证据归入本次故障，不扩大修改范围。

## 用户验收

1. 双端更新并重启，在同一地块派遣双方雇员。分别确认右侧雇员栏及全选只包含本方人员。
2. 设置敌对，确认对方人物在地图中可见，显示敌对身份，选择与攻击按关系和控制权限处理。
3. 客人观察站立、移动、倒地的雇员，确认模型、装备、携带物和名字正常；换图及重新入图后继续观察。
4. 切换友好、中立、敌对，确认不改变人员归属、不重复生成角色，双方资产及各自控制权限正常。
